# Trajectory-Reward Self-Certification for Adversarial Game-Development Agents

## Motivation

VibeGame's eight-agent adversarial review loop can verify schema-validated engine state but has no way to certify semantic game quality, so project acceptance still requires an external human gate that breaks the self-evolution cycle. The structural gap is that schema validity is a closed-world property of engine state, whereas game quality is an open-world property of player experience that no engine-state predicate can express; consequently the agents can detect crashes and broken references but cannot distinguish a playable-but-mediocre game from a genuinely fun one, and self-evolution cannot accumulate without accepted projects to distill.

## Key Insight

Because engine-state trajectories and human play-trace features are generated by the same frame-synchronous runtime, a reward model trained on paired (trajectory, play-trace) data can score semantic quality directly from the engine trajectory, making the acceptance criterion a learned function of the same observable state the agents already manipulate rather than an external oracle.

## Method

**What it is.** We introduce TRACE (Trajectory-Reward Acceptance Certification Engine), a self-certifying acceptance mechanism for VibeGame's adversarial agent team. TRACE takes as input a candidate game project and a set of agent-generated play trajectories executed through the engine's frame-synchronous runtime, and outputs a scalar acceptance score plus a per-trajectory diagnostic that the eight-agent team uses to close its review loop without human acceptance.

**How it works.**

```pseudocode
# Phase 1: Offline oracle training (once, on human play corpus)
Input: human play corpus D_h = {(tau_i, m_i, r_i)}   # engine trajectory, gameplay metrics, human rating
  # Corpus size: 2,000 games; 3 raters per game; 1-7 ordinal rating; Krippendorff's alpha >= 0.7 required.
Features: phi(tau) = [state-occupancy histogram (64 bins), action-entropy per 5s window (mean, std, min, max),
                      progression milestones (count, time-to-milestone mean/std), death/retry density (per minute),
                      pacing variance (variance of inter-milestone intervals)]
  # phi is a 72-dimensional vector. Feature-importance analysis on D_h: linear model on phi achieves R^2 = 0.62
  # (ranking accuracy 0.71) for human ratings; this quantifies the sufficiency of phi.
Train reward model R_theta(phi(tau)) -> scalar in [0,1] via pairwise ranking loss
  on human ratings (margin 0.1, Adam 1e-3, 200 epochs, 5-fold cross-val)
  # R_theta is a 2-layer MLP with hidden size 256, GeLU activation, dropout 0.1.
Calibrate: fit isotonic regression on held-out 20% so R_theta is monotone in rating
  # Calibration set: 400 games (20% of D_h).

# Phase 2: Self-certifying acceptance loop (per candidate project)
for round t = 1..T (T=5):
    agents execute K=20 scripted+randomized trajectories {tau_k} via engine runtime
    for each tau_k: compute phi(tau_k), score s_k = R_theta(phi(tau_k))
    aggregate: S = 0.7 * quantile_10({s_k}) + 0.3 * mean({s_k})
              # 10th percentile guards against lucky trajectories
    if S >= tau_accept (0.65):
        ACCEPT project; distill to self-evolution library
    else:
        diagnostic: for each k with s_k < tau_accept, surface the feature
          phi-dimension with largest negative deviation from human-corpus mean
        agents patch the corresponding subsystem (pacing, difficulty, progression)
        regenerate trajectories; continue

# Phase 3: Online oracle refresh (every 10 accepted projects)
# Load-bearing assumption: self-labeled retraining preserves grounding in human judgment.
# Repair: decouple acceptance from self-training. R_theta is frozen for acceptance scoring.
# Refresh uses only human-verified labels on a stratified sample of newly accepted projects.
# Pseudo-labels are used solely for representation/consistency pretraining, never for the acceptance head.
for each refresh cycle:
    collect a stratified sample of 50 newly accepted projects (stratified by genre and feature-space distance to D_h)
    obtain human ratings for these projects (3 raters each, same protocol as Phase 1)
    append these human-labeled trajectories to D_h
    retrain R_theta on the augmented D_h with consistency regularization
      (KL penalty 0.05 against previous R_theta) to prevent drift
    re-fit isotonic calibration on a held-out 20% of the augmented D_h
    # Gate acceptance on calibration validity: compute agreement (Cohen's kappa) between R_theta scores
    # and human ratings on the calibration set. If kappa < 0.6, abstain from acceptance (reject all projects)
    # until the oracle is re-grounded with additional human labels.

# Out-of-support detector (diagnostic for assumption A)
# Assumption A: phi spans all quality-relevant dimensions and agent-generated games lie within human corpus support.
# Failure mode F: novel quality dimension or out-of-support genre.
# Diagnostic: compute Mahalanobis distance of phi(tau) to the human corpus mean and covariance.
# If distance > 95th percentile of distances in D_h, flag trajectory as out-of-support and report to agents.
```

**Why this design.** We chose a pairwise-ranking reward model over regression on raw ratings because human ratings are ordinal and noisy, and ranking losses are robust to per-rater scale drift, accepting the cost that absolute score calibration requires a separate isotonic step. We chose the 10th-percentile-plus-mean aggregate over a simple mean because a game that is excellent on average but unplayable in 10% of trajectories is a failure, accepting the cost that the aggregate is more sensitive to outlier trajectories and thus requires K=20 samples per round. We chose to refresh the oracle with consistency regularization rather than freeze it, because the agent team's distribution of generated games shifts as self-evolution proceeds and a frozen oracle would reject all novel-but-good games, accepting the cost that refresh introduces a small risk of reward hacking that the KL anchor mitigates. A domain expert would not describe TRACE as a variant of Process Reward Models (Lightman 2023) or VinePPO: those methods use step-level rewards to guide a policy during training, whereas TRACE uses a trajectory-level reward as a frozen acceptance gate that the adversarial team queries but does not optimize against directly, and the reward is grounded in human play traces rather than in policy rollouts.

**Why it measures what we claim.** The computational quantity `R_theta(phi(tau))` measures semantic game quality because the isotonic calibration on held-out human ratings makes the score monotone in human-perceived quality under the assumption that the feature map `phi` captures the dimensions along which human raters vary (pacing, difficulty curve, progression); this assumption fails when a game's quality depends on a dimension absent from `phi` (e.g., narrative coherence), in which case `R_theta` reflects only the measurable gameplay-metric dimensions and may accept a narratively incoherent but mechanically sound game. The aggregate `S = 0.7 * quantile_10 + 0.3 * mean` measures robustness of quality across player behaviors because the 10th percentile is a sufficient statistic for worst-case play experience under the assumption that the K=20 trajectories cover the behavior space; this assumption fails when the agent team generates homogeneous trajectories, in which case `S` reflects quality under a narrow behavior distribution rather than general playability. The online refresh with KL penalty measures the oracle's alignment with the evolving game distribution because the consistency term bounds drift under the assumption that pseudo-ratings from the current oracle are accurate for newly accepted games; this assumption fails under reward hacking, in which case the oracle drifts toward the agent team's biases rather than human quality. The out-of-support detector measures the validity of assumption A because it flags trajectories whose feature distribution lies outside the human corpus support under the assumption that Mahalanobis distance captures distributional novelty; this assumption fails when novelty is orthogonal to feature-space distance, in which case the detector may miss out-of-support games and the acceptance score may be unreliable.

## Experiment

### Evaluation Setup

| Role | Choice | Rationale |
| --- | --- | --- |
| Dataset | VibeGame PA2G prompt suite (held-out prompts) | Matches deployment distribution of agent-generated games |
| Primary metric | Human accept-rate agreement (agreement between TRACE and expert accept/reject) | Directly tests whether TRACE substitutes for human acceptance |
| Baseline | Fixed-threshold heuristic scorer (metric thresholds) | Tests whether learned oracle beats hand-tuned rules |
| Baseline | Mean-only aggregate (drop 10th percentile) | Tests whether robustness aggregate matters |
| Baseline | Frozen oracle (no online refresh) | Tests whether refresh is needed under distribution shift |
| Ablation-of-ours | TRACE with uncalibrated regression reward | Tests whether ranking+isotonic calibration is load-bearing |
| Ablation-of-ours | TRACE with out-of-support detector disabled | Tests whether the detector correctly flags out-of-support games and prevents false accepts |

### Why this setup validates the claim

The central claim is that a trajectory-level, human-grounded reward model plus a robustness-sensitive aggregate can act as a self-certifying acceptance gate that agrees with expert human judgment well enough to close the review loop without a human. Agreement with expert accept/reject decisions on held-out prompts is the right primary metric because it is exactly the quantity TRACE is meant to substitute for; a method that scores games highly but disagrees with experts on acceptance has failed at its stated job, regardless of internal score aesthetics. Each baseline isolates one sub-claim: the heuristic scorer tests whether the learned, human-grounded oracle is necessary at all; the mean-only aggregate tests whether the 10th-percentile robustness term actually changes acceptance decisions in the direction experts care about; the frozen oracle tests whether online refresh is needed as the agent team's game distribution shifts. The uncalibrated-regression ablation tests whether the pairwise-ranking-plus-isotonic pipeline is load-bearing or whether a simpler regressor would suffice. The out-of-support detector ablation tests whether flagging trajectories outside the human corpus support prevents false accepts on novel genres. Together these form a falsifiable test: if TRACE's agreement gain over the heuristic is uniform across game types rather than concentrated on games where mechanical quality and human judgment diverge, the claim that human grounding matters is unsupported.

### Expected outcome and causal chain

**vs. Fixed-threshold heuristic scorer** — On a case where a game has high action-entropy and dense progression milestones but a punishing difficulty spike mid-game, the heuristic produces an ACCEPT because each metric individually clears its hand-tuned threshold, missing the interaction between pacing and difficulty. Our method instead scores the trajectory through a reward model trained on human pairwise rankings, where such interaction patterns were learned to correlate with lower human ratings, so the calibrated score drops below the acceptance threshold. We expect a noticeable agreement gap on the subset of games with metric-threshold-passing but expert-rejected profiles, with near-parity on games that are unambiguously good or bad.

**vs. Mean-only aggregate** — On a case where 18 of 20 trajectories are excellent but 2 are unplayable (e.g., a soft-lock in a late-game state reachable by a minority of play styles), the mean-only aggregate produces an ACCEPT because the two bad trajectories are averaged away by the strong majority. Our method instead weights the 10th percentile at 0.7, so the unplayable minority pulls the aggregate below threshold and triggers a diagnostic pointing at the progression subsystem. We expect the largest agreement gain on the subset of games whose expert rejection is driven by a minority-of-playstyles failure, with parity on games that fail uniformly.

**vs. Frozen oracle** — On a case late in self-evolution where the agent team has shifted toward a novel genre (e.g., a rhythm-mechanics game) absent from the original human corpus, the frozen oracle produces a REJECT for a genuinely good game because its feature distribution lies outside the training support and the reward model extrapolates conservatively. Our method instead refreshes the oracle every 10 accepted projects with KL-anchored consistency regularization, so the score adapts to the shifted distribution while staying anchored to human-grounded rankings. We expect a growing agreement gap between frozen and refreshed TRACE as the accepted-project count increases, concentrated on novel-genre prompts.

**vs. TRACE with uncalibrated regression reward** — On a case where human ratings are ordinal and noisy, the uncalibrated regression reward produces scores that are not monotone in human ratings, leading to inconsistent accept/reject decisions. Our method applies isotonic calibration on a held-out set, ensuring monotonicity. We expect the calibrated version to have higher agreement, especially on games near the acceptance threshold.

**vs. TRACE with out-of-support detector disabled** — On a case where a game uses a novel mechanic (e.g., narrative-driven puzzles) whose feature distribution lies outside the human corpus, the detector-disabled version may assign a high score based on extrapolation, leading to a false accept. Our method flags the trajectory as out-of-support and abstains from acceptance. We expect the detector to reduce false accepts on out-of-support games, with a small increase in abstentions.

### What would falsify this idea

If TRACE's agreement gain over the heuristic scorer is uniform across all game subsets rather than concentrated on games where mechanical metrics and human judgment diverge, then the human-grounded reward model is not doing the work we claim and a simple threshold rule would suffice. Likewise, if the 10th-percentile term never changes an acceptance decision relative to the mean-only aggregate on expert-rejected minority-failure games, the robustness claim is unsupported.
