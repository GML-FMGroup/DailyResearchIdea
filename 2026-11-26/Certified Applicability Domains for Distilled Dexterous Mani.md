# Certified Applicability Domains for Distilled Dexterous Manipulation Programs

## Motivation

Distillation-based dexterous manipulation frameworks such as PyRUA-Dex (arxiv:2611.33144) condense successful coding-agent explorations into a single programmatic policy plus a task library, but the distillation establishes no closure rule: the program is treated as a total function over the task distribution even though it was only ever validated on the finite set of skills the exploration agents happened to discover. The same structural gap recurs across the tree — DexHandDiff (6060599c) generates goal-adaptive guidance without certifying it outside training distributions, and Scaffolding-with-VLMs (venue:neurips:2025:586c9c63c36d) produces coarse scaffolds whose validity is only checked by downstream RL success on the tasks it was given. In every case the generator's domain boundary is inherited by assumption rather than checked, so deployment silently executes out-of-domain compositions with no flag.

## Key Insight

Compositional closure of a distilled skill library is a property that can be audited by adversarial enumeration against a simulator-grounded validity oracle, and the resulting certified domain — a partial-function boundary rather than an assumed-total generator — is itself the deployable artifact.

## Method

**A. What it is.** We introduce CADA (Certified Applicability Domain Audit), a post-distillation layer that wraps a PyRUA-Dex-style programmatic policy `P` and its task library `L` with (i) a skill-enumeration and compositional-closure audit against a simulator validity oracle, and (ii) a certified applicability domain `D(P) ⊆ C` attached to `P`, where `C` is the space of skill compositions. Inputs: program `P`, library `L`, simulator `S`, composition grammar `G`. Outputs: a pruned/annotated program `P'` that either executes or explicitly raises `OutOfDomain(composition)` for any queried composition, plus the certificate `D(P')`.

**Load-bearing assumption (stated explicitly).** CADA's audit has a non-empty target set only if the unguarded distilled program `P` behaves as a total function that silently mis-executes on some out-of-domain compositions — i.e., it executes without raising and produces a wrong outcome. This is an empirical premise, not a structural guarantee: a programmatic policy may instead raise on unmet preconditions or fail cleanly. We therefore measure the silent-failure rate of the unguarded `P` on the sampled compositions in Phase 2 before any guard insertion, and report it as a measured quantity. If the unguarded program is already effectively partial (silent-failure rate near zero), the certificate `D(P')` is still defined as the simulator-grounded boundary over `C`, but the guard-synthesis step is evaluated against whatever failure mode the unguarded program actually exhibits (silent, raised, or clean-fail), and the silent-failure rate is demoted from premise to measured outcome.

**B. How it works.**

```pseudocode
INPUT: program P, skill library L (|L|=n), simulator S, composition grammar G,
       novelty radius r=0.15 (normalized parameter-space), audit budget B=2000 compositions,
       coverage threshold tau=0.95

PHASE 1 — Enumerate candidate compositions
  C_enum <- grammar_enumeration(G, L, max_depth=4)        # all syntactically legal chains
  C_novel <- sample_stratified(C_enum, B, strata=skill-pair signature)

PHASE 2 — Oracle labeling (simulator-grounded, not model confidence)
  for c in C_novel:
      outcome[c] <- rollout(P, c, S, n_trials=20)         # success / failure / invalid-precondition
      valid[c]   <- outcome[c] == success  AND  min_pairwise_state_dist(c) > r
  # measured premise: silent_failure_rate_unguarded = |{c : outcome[c]==failure and no raise}| / |C_novel|

PHASE 3 — Coverage certification (compositional closure test)
  D_cert <- { c in C_novel : valid[c] }
  coverage <- |D_cert| / |C_novel|
  if coverage < tau:
      P' <- P with per-composition guards inserted: guard(c) fires iff c ∉ D_cert
      # guards are generated by the coding agent from the failure traces, then re-audited
      re-run PHASE 2 on C_novel \ D_cert with P'
  else:
      P' <- P

PHASE 4 — Attach certificate
  D(P') <- convex-hull-free explicit set D_cert ∪ {c : guard(c) proven to fire}
  return (P', D(P'), coverage, failure_taxonomy, silent_failure_rate_unguarded)
```

**C. Why this design.** We chose simulator-grounded oracle labeling over any learned out-of-distribution score (e.g., a language-model confidence head) because PyRUA-Dex's distillation already has access to the simulator during refinement, and a learned OOD head is exactly the calibrated-log-prob gating signal that prior work has shown unreliable for task correctness; the cost we accept is that the audit is simulation-bound and does not transfer to real-world compositions without a real-world oracle. We chose explicit per-composition guards generated by the coding agent over a single global retrain because guards preserve the distilled program's verified behavior on in-domain compositions while making out-of-domain behavior a named, inspectable failure rather than a silent mis-execution; the cost is a larger program surface and guard-maintenance overhead. We chose stratified sampling by skill-pair signature over uniform sampling because compositional failure modes cluster at skill boundaries (e.g., pen-cap after bottle-unscrew), so uniform sampling under-covers exactly the boundary region the audit exists to certify; the cost is a biased estimate of overall coverage, which we report separately from the boundary-focused certificate. A domain expert would not describe CADA as a variant of PyRUA-Dex's distillation, because PyRUA-Dex distills successful explorations into a total program whereas CADA's load-bearing operation is the adversarial enumeration plus guard insertion that converts the program into a partial function with an attached domain — a step PyRUA-Dex does not contain.

**D. Why it measures what we claim.** The computational quantity `coverage = |D_cert|/|C_novel|` measures compositional closure of the distilled program because we assume the stratified sample `C_novel` is representative of the boundary region of the composition grammar; this assumption fails when the grammar's legal compositions include physically infeasible chains that the simulator rejects for reasons unrelated to the program's skill set, in which case coverage reflects simulator feasibility rather than program coverage. The quantity `valid[c]` measures whether composition `c` lies in the program's true applicability domain because we assume simulator success across 20 trials with a novelty radius `r` is equivalent to the program having a robust policy for `c`; this assumption fails when the simulator's randomization is narrower than deployment conditions, in which case `valid[c]` reflects in-simulation robustness rather than real-world domain membership. The guard predicate `guard(c)` measures out-of-domain detection because we assume the coding agent's guard generated from failure traces fires exactly on the failure equivalence class; this assumption fails when two compositions share a guard signature but differ physically, in which case the guard reflects a coarse failure taxonomy rather than the exact domain boundary. The quantity `silent_failure_rate_unguarded` measures the fraction of out-of-domain compositions on which the unguarded program executes without raising and produces a wrong outcome because we assume the simulator's success/failure labeling is the ground truth for correctness; this assumption fails when the simulator's success criterion is more permissive than the deployment task, in which case the measured rate reflects simulator leniency rather than true silent mis-execution.

## Experiment

### Evaluation Setup

| Role | Choice | Rationale |
| --- | --- | --- |
| Dataset | Bench2Dex + DexJoCo composition suites | Published programmatic-policy benchmarks with compositional task structure |
| Primary metric | Out-of-domain silent-failure rate on held-out compositions | Directly measures whether guards catch what the program mis-executes |
| Secondary metric | Guard precision/recall against oracle-labeled failure set | Measures whether guards fire exactly on the failure equivalence class |
| Secondary metric | Unguarded silent-failure rate (premise check) | Measures whether the distilled program is a total function before any guard insertion |
| Baseline | PyRUA-Dex unguarded program | Tests whether the distilled program is already a total function |
| Baseline | Global-retrain program (single retrain on failures) | Tests whether per-composition guards beat a monolithic fix |
| Baseline | Learned OOD confidence head | Tests whether simulator-grounded oracle beats confidence gating |
| Ablation-of-ours | CADA with uniform sampling (no stratification) | Isolates the boundary-focused sampling contribution |
| Ablation-of-ours | CADA with reduced budget (B=200, n_trials=5) | Tests tractability and variance of coverage/silent-failure estimates |

### Why this setup validates the claim

The central claim is that a PyRUA-Dex-style distilled program is a total function that silently mis-executes on compositions outside its true applicability domain, and that CADA's enumeration-plus-guard insertion converts it into a partial function whose out-of-domain behavior is a named, inspectable failure. The unguarded PyRUA-Dex baseline tests the first half of that claim: if the distilled program already raises or cleanly fails on out-of-domain compositions, CADA has nothing to certify and the idea is dead. The global-retrain baseline tests whether the guard mechanism is doing work that a single retrain could not — if retraining matches guard insertion on silent-failure rate, the per-composition guard design is unjustified overhead. The learned OOD confidence head tests whether the simulator-grounded oracle is load-bearing: if a confidence head achieves the same silent-failure reduction, our choice of oracle is not the causal driver. The uniform-sampling ablation tests whether the stratification is what concentrates coverage on the boundary region. The reduced-budget ablation tests whether the audit is tractable at B=200, n_trials=5 and reports variance of coverage and silent-failure estimates across 5 random seeds. The primary metric — out-of-domain silent-failure rate, i.e. the fraction of queried compositions where the program executes without raising and produces a wrong outcome — is the right one because it is exactly the quantity a certificate is supposed to bound; success rate on in-domain compositions would be blind to the failure mode CADA exists to catch. The guard precision/recall metric directly measures whether the guard predicate fires exactly on the oracle-labeled failure set, which is the operational meaning of the certificate.

### Expected outcome and causal chain

**vs. PyRUA-Dex unguarded program** — On a composition like bottle-unscrew chained into pen-cap, the unguarded program executes the second skill with the post-unscrew hand pose because its distilled program has no precondition check at the skill boundary, producing a silent mis-execution the caller cannot distinguish from success. Our method instead inserts a guard at that boundary because Phase 2's stratified sample covers the skill-pair signature and Phase 3's failure traces reveal the precondition mismatch, so we expect a large gap in silent-failure rate concentrated on multi-skill boundary compositions and near-parity on single-skill compositions. We also report the measured unguarded silent-failure rate as the premise check: if it is near zero, the gap will be near zero and the premise is falsified.

**vs. Global-retrain program** — On a composition where the failure is a narrow precondition violation (e.g. object orientation off by a few degrees after relocation), the global retrain smooths the boundary by shifting the policy's behavior everywhere, degrading previously-verified in-domain compositions while still not raising on the out-of-domain case. Our method instead leaves the distilled program untouched on in-domain compositions and adds a guard that fires only on the failing equivalence class, so we expect the retrain to show collateral in-domain regressions alongside a smaller silent-failure reduction, while ours shows silent-failure reduction with in-domain behavior held fixed.

**vs. Learned OOD confidence head** — On a composition that is syntactically legal and semantically plausible but physically infeasible (e.g. a chain requiring a grasp the hand cannot form), the confidence head assigns high confidence because the composition resembles in-distribution skill chains in token space, so it fails to raise and the program mis-executes. Our method instead labels that composition invalid through simulator rollouts, so the guard fires regardless of surface similarity, and we expect the confidence head to show high silent-failure rate specifically on the physically-infeasible subset while ours stays low there and both are comparable on the surface-novel subset.

### What would falsify this idea

If the unguarded PyRUA-Dex program already raises or cleanly fails on nearly all out-of-domain compositions — i.e. the silent-failure rate is near zero before any guard insertion — then the premise that the distilled program is a total function is wrong and CADA's load-bearing operation has nothing to act on. Equally, if the silent-failure reduction from CADA is uniform across boundary and non-boundary compositions rather than concentrated on the skill-boundary subset the stratification targets, the causal story about boundary-clustered failure modes is not what is driving the result.
