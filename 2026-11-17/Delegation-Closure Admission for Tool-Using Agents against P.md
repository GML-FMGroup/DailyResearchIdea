# Delegation-Closure Admission for Tool-Using Agents against Prompt Injection

## Motivation

Runtime defenses against prompt injection in tool-using agents still treat action authorization as a per-action predicate, so a call is admitted when its target is locally covered by a rule, without any invariant guaranteeing that the chain of delegations producing that target is itself closed under composition. SPILLWAY makes this concrete: it admits a call if each target value is returned by a read-only tool in a typed field or is covered by a fixed delegation rule, but a fixed rule set has no closure operator, so a target reachable only through a finite composition of legitimate delegations (A→B, B→C, hence A→C) is either wrongly rejected or, if the rule set is widened to cover it, opens an unverified path that an injected instruction can exploit. The root cause is structural: flat rule matching cannot distinguish a target reached by composing authorized delegations from a target that merely matches a rule's surface pattern, because the composition structure is never represented.

## Key Insight

Target admission becomes a fixpoint over a delegation-rule graph rather than a per-action match, so an attacker's target is admitted only if it lies in the least fixed point of the closure generated by delegations whose intermediate targets are themselves already in the closure — a property no flat rule set or per-action privilege check can express.

## Method

**What it is.** We introduce DCAA (Delegation-Closure Admission Agent), a runtime defense that replaces SPILLWAY's flat fixed delegation rules with a compositional closure operator over the user task's authorized target set. Its inputs are (i) the user task text, (ii) the typed tool-return fields observed so far, (iii) a delegation-rule graph D whose edges are (source-target-set, delegate-target, privilege-scope) triples, and (iv) a proposed tool call with its target value; its output is an admit/refuse decision plus the closure derivation that justifies admission (or the missing-edge witness that justifies refusal).

**Load-bearing assumption (stated explicitly).** DCAA assumes that the delegation-rule graph D and its privilege lattice L can be authored and maintained such that every edge is individually sound and the least-fixpoint closure over D never composes individually-in-scope edges into a privilege-escalating or attacker-exploitable target, so that membership in the closure is a sound authorization signal. This is the classic transitive-privilege-escalation / confused-deputy problem: a least fixed point is monotone and composition-blind to scope interaction, and closure over edges gated only by 'scope_i <= privilege of the current action' cannot detect that edge A->B is low-privilege and B->C is high-privilege while the composed A->C exceeds the user's authority, because the fixpoint operator has no representation of the composed privilege, only of each edge's scope. To make the assumption hold, DCAA uses an attenuating closure (step 2 below): each edge carries an explicit capability/authority set and admits t_i only if scope_i is a subset (attenuation) of the intersection of the scopes of all antecedents in S_i, so composed privilege is computed along the derivation rather than checked per edge; cycles in the derivation graph G are forbidden (or every path must have a strictly decreasing scope measure) so no fixpoint can be reached via a privilege-escalating cycle.

**How it works.**

```pseudocode
# Inputs: user_task T, typed returns R (read-only tool outputs),
#         delegation-rule graph D = {(S_i, t_i, scope_i)},
#         proposed call c with target value tau(c)
# Hyperparams: max_closure_depth K=8 (safety cap), privilege lattice L
# Each scope_i is a capability/authority set drawn from L.

1. SEED:  A_0 = { target values appearing verbatim in T }
          ∪ { typed-field values in R whose field is read-only }
          scope(A_0) = the user's authority set from T (intersected with
          the declared scopes of the read-only tools that produced R).
2. ATTENUATING CLOSURE FIXPOINT:
      A <- A_0;  scope(A) <- scope(A_0)
      repeat until A stabilizes or depth > K:
          for each rule (S_i, t_i, scope_i) in D:
              if S_i ⊆ A and t_i ∉ A:
                  # attenuation: scope_i must be a subset of the
                  # intersection of the scopes of all antecedents
                  if scope_i ⊆ ⋂_{s ∈ S_i} scope(s):
                      # cycle guard: forbid adding t_i if it would
                      # create a cycle in G, or require a strictly
                      # decreasing scope measure along every path
                      if adding edge (S_i -> t_i) keeps G acyclic
                         (or scope_i ⊂ scope(s) for all s ∈ S_i):
                          A <- A ∪ {t_i}
                          scope(t_i) <- scope_i
                          record edge (S_i -> t_i) in derivation graph G
3. ADMIT iff tau(c) ∈ A
      if admitted: emit G's derivation path from A_0 to tau(c)
      if refused: emit the minimal missing-edge witness
          (S_i, t_i) such that S_i ⊆ A but t_i = tau(c) ∉ A
4. SANITIZE (unchanged from SPILLWAY): strip instruction-like regions
      matched by fixed rules before the model reads R; retain spans as evidence.
5. LOCAL JUDGE (unchanged): may restore a refused call only if
      tau(c) ∉ removed-span set; the judge cannot add edges to D.
```

**Why this design.** We chose a least-fixpoint closure over an iterative re-check of SPILLWAY's flat rule predicate because flat matching cannot represent that a target reached via A→B→C is authorized exactly when A→B and B→C are, accepting the cost that the rule graph must be explicitly maintained and that closure depth is bounded by K=8 (deeper legitimate chains fall back to refusal). We chose to seed the closure only from typed read-only returns and verbatim user-task targets rather than from free-text tool output because free text is the attacker's surface, accepting the cost that tools returning unstructured text cannot contribute seeds and their targets are refused. We chose to emit the derivation path or the minimal missing-edge witness rather than a binary decision because auditability is the property that distinguishes a closure from a black-box filter, accepting the cost of storing the derivation graph per call. We chose to keep SPILLWAY's deterministic sanitizer and local judge rather than replacing them, because the closure operates on the admission decision while sanitization operates on what the model reads — these are orthogonal surfaces, and a domain expert would not describe DCAA as a variant of SPILLWAY's rule matching: SPILLWAY checks a target against a fixed rule's surface pattern, whereas DCAA computes a least fixed point over the rule graph and admits only targets with a finite derivation whose every intermediate is itself derived; the matched prior method (SPILLWAY's flat admission) cannot express this composition, and no widening of its rule set can, because widening admits targets without derivations.

**Why it measures what we claim.** The closure set A measures the authorized target set under delegation composition because the least-fixpoint operator is, by construction, the smallest set closed under the delegation rules seeded by the user task and typed returns; this assumption fails when the rule graph D contains a cycle whose edges are individually in-scope but whose composition escalates privilege (e.g., a low-privilege edge and a high-privilege edge sharing an intermediate), in which case A reflects a privilege-escalating closure rather than a legitimate one — which is why step 2 gates each edge by the privilege lattice L and requires attenuation (scope_i ⊆ ⋂ scope(s)) and acyclicity. The missing-edge witness measures the structural reason for refusal because it is the unique minimal rule whose antecedent is satisfied but whose consequent is not in A; this assumption fails when multiple minimal witnesses exist and the emitted one is not the one the attacker exploited, in which case the witness reflects a sufficient rather than a necessary obstruction. The derivation path measures auditability because each edge in G is recorded with its rule identity and privilege scope; this assumption fails when D is edited between the closure computation and the audit review, in which case the path reflects a stale rule graph rather than the one in force at decision time.

## Experiment

### Evaluation Setup

| Role | Choice | Rationale |
| --- | --- | --- |
| Dataset | AgentDojo (plus ASB scenarios) | IPI benchmark with typed tool returns and multi-step tasks |
| Primary metric | In-scope attack success rate (ASR) at matched utility | Detects redirected targets, not just refusals |
| Baseline | SPILLWAY (flat admission) | Isolates the compositional-closure sub-claim |
| Baseline | DRIFT (dynamic rule validator) | Tests whether closure beats rule-deviation monitoring |
| Baseline | MELON (masked re-execution) | Tests whether closure beats re-execution detection |
| Ablation-of-ours | DCAA with flat D (no transitive closure) | Shows composition, not seeding, drives the gain |
| Ablation-of-ours | DCAA with per-edge scope gate (no attenuation) | Shows attenuation is necessary for soundness under composition |
| Ablation-of-ours | DCAA with cycles allowed in G | Shows cycle guard is necessary to prevent privilege-escalating fixpoints |

### Why this setup validates the claim

The central claim is that admission should be decided by a least-fixpoint closure over a delegation-rule graph, not by flat rule matching, so that targets reachable only through legitimate multi-hop delegation are admitted while underived targets are refused. SPILLWAY is the decisive baseline: it shares our sanitizer and local judge but checks targets against a fixed surface rule, so any gap between SPILLWAY and DCAA on multi-hop-delegation tasks is attributable to the closure operator alone. DRIFT and MELON test the sub-claim from the other direction — they are strong non-closure defenses whose mechanisms (rule-deviation monitoring, masked re-execution) are blind to whether a target has a finite derivation, so they should refuse or miss chains that DCAA admits or blocks by construction. The ablation with a flat rule set (no transitive closure) is the falsification lever: if closure is doing the work, removing transitivity should collapse DCAA toward SPILLWAY. The attenuation and cycle-guard ablations test the load-bearing assumption: if the gain persists without attenuation or with cycles allowed, then the closure is unsound under composition and the central claim is wrong. In-scope ASR at matched utility is the right metric because it counts only redirects to attacker targets, so a defense cannot win by refusing everything; utility parity is the guard against that degenerate strategy. To verify that the benchmark contains genuine multi-hop delegation tasks, we report a per-suite hop-depth histogram (number of delegation edges in the shortest derivation from A_0 to each legitimate target) and confirm that at least 30% of legitimate targets in the multi-hop suites require depth ≥ 2; if not, the ablation cannot separate closure from seeding and the causal claim is untested.

### Expected outcome and causal chain

**vs. SPILLWAY** — On a task where the user authorizes paying a vendor reached via a typed invoice that delegates to a sub-account, SPILLWAY refuses because its flat rule matches only the surface target and has no edge for the sub-account, so it either blocks a legitimate call or, if the rule set is widened, admits an attacker target that superficially matches the widened pattern. Our method instead derives the sub-account through the A→B→C closure and admits exactly the derived target, so we expect a noticeable ASR gap concentrated on multi-hop-delegation suites with near-parity on single-hop suites.

**vs. DRIFT** — On a case where a poisoned memory entry inserts a plausible intermediate target that satisfies each local privilege check, DRIFT's dynamic validator sees a deviation that stays within privilege scope and lets it through because it monitors per-step deviation rather than global derivability from the user seed. Our method instead refuses because the intermediate has no derivation path from A_0, so we expect DRIFT to show elevated in-scope ASR on memory-poisoning and multi-hop subsets where DCAA stays near the floor, with utility parity elsewhere.

**vs. MELON** — On a case where the malicious instruction is a short paraphrase that leaves the agent's action similar under a masked user prompt, MELON's re-execution similarity check flags no attack because the action is stable under masking, and it admits the redirected call. Our method instead refuses on target grounds independent of action similarity, so we expect MELON to leak on low-similarity-shift attacks while DCAA holds, showing a gap on the paraphrase subset but parity on templated injections.

**vs. DCAA with per-edge scope gate (no attenuation)** — On a case where a low-privilege edge A→B and a high-privilege edge B→C compose to a target C that exceeds the user's authority, the per-edge gate admits both edges because each scope_i is individually ≤ the current action's privilege, so the closure includes C and the attacker's target is admitted. Our attenuated closure refuses because scope(C) = scope_i for B→C is not a subset of scope(B) ∩ scope(A), so C is not added. We expect the per-edge-gate ablation to show elevated in-scope ASR on privilege-escalation attack suites while full DCAA stays near the floor.

**vs. DCAA with cycles allowed in G** — On a case where a cycle in D (e.g., A→B→A) allows the fixpoint to reach a target via a privilege-escalating loop, the cycle-allowed ablation admits the target because the fixpoint stabilizes after the loop, whereas full DCAA forbids the cycle and refuses. We expect the cycle-allowed ablation to show elevated in-scope ASR on cyclic-delegation attack suites.

### What would falsify this idea

If DCAA's gain over SPILLWAY is uniform across single-hop and multi-hop subsets rather than concentrated on multi-hop delegation cases, or if the flat-D ablation matches full DCAA, then the closure operator is not the causal mechanism and the central claim is wrong. Additionally, if the attenuation or cycle-guard ablations show no increase in ASR relative to full DCAA, then the load-bearing assumption is not load-bearing and the method's soundness story is unsupported.
